# Contributing

1. Fork the repository and create a focused branch.
2. Run `npm run check` before opening a pull request.
3. Add or update a test for API behavior and update docs when user-facing behavior changes.
4. Keep real-cluster changes safe by preserving read-only defaults and scoped RBAC.

Pull requests should explain the user impact, verification performed, and any Kubernetes or Docker version assumptions. Use the issue templates for bugs and feature proposals.
